## Fixture protocol and adapters

The fixture's Game data is `[opcode:u8, card_a:u32LE, card_b:u32LE, card_c:u32LE, viewer:u8]` (exactly 14 bytes). Reject wrong length/opcode and invalid referenced IDs. IDs come from admitted Deal/Spawn results or the parsed current allocator; they are never inferred from process allocation. Reserve opcodes:

- 0: no-op, with Continue when active.
- 1: Begin plus the fixed mechanical workload below.
- 2/3: Commit/Rollback the captured active ID; opcode 3 may be followed by a cancellation annotation on card_a.
- 4: Begin + Peek(card_b,viewer) + Move(card_a,All Aux) + Reveal(card_a), then wait.
- 5: active Reveal(card_a) twice (idempotent request test).
- 6: active Move(card_a,None Aux) + Move(card_a,All Aux) + Reveal(card_a), then wait.
- 7: active Move(card_a,None Aux).
- 8: active Despawn(card_a).
- 9: active Spawn in None Aux + Peek(new_id,viewer) + Despawn(new_id).
- 10: Begin + Spawn + Rollback in one accepted verdict.
- 11: ordinary/grouped Peek(card_a,viewer), with a first Continue only when active.
- 12: ordinary Move(card_a,All Aux) then Begin (legacy owed-hidden preparation).
- 13: Begin only.

Put the first Continue in active commands except the first terminal command; Begin commands require no active group. Do not substitute Begin for membership. On a normal incoming Reveal, emit Continue if active and otherwise accept without group effects; do not execute the next payment/move automatically. The next Game opcode is the explicit continuation, allowing the host test to save the public-fulfillment boundary.

`decide_bytes` parses the actual engine request with `decide::parse`, creates `EffectProjection::from_decide`, constructs the script from that parsed request, then validates it with project_verdict. Encode the SDK Verdict with those exact effects. Advance a tiny versioned plugin-state command counter only on accepted group commands; Reveal callbacks preserve it. No scenario position lives in wasm memory. Setup Genesis/Join/Deal actions are accepted without trying to project SDK's incomplete generic Deal/Other action representation; all group operations and Reveal continuations use from_decide. Unsupported in-group structural actions must never reach the fixture through normal admission.

NativeFixture implements sim PluginModule with abi_version=1, calling these same byte functions and decoding their replies. The wasm fixture uses real SDK exports and is loaded/hardened through agni-engine-host. `view_bytes` parses a real view request and emits deterministic status for face names available in that parsed projection and the command counter, allowing view-overlay checks; it never constructs an authoritative group or writes plugin state. This diagnoses supplied face information rather than replacing visibility policy. Assert actual display audiences with engine TableView and ClientSession::table: a public face retained in authoritative state is not necessarily displayed in every private placement.

Projection failures in this honest fixture return a refusal. Engine-invalid-verdict tests use a separately named adversarial native/WAT adapter, so they actually exercise the engine guard instead of merely testing that the SDK refused to emit the effect. Do not let that adapter leak into the ordinary admitted corpus.

## Differential driver and comparison contract

Setup two seats, declared neutral zones and counter declarations through actual log actions. Use All/Owner/None zones of kind Aux to avoid unintended state/token shedding; add a separate Deck/Discard declaration for the specific shedding guard vector. Include built-in Hand/Board in one parsing/audience case. All faces are synthetic test names, with one public face carrying nondefault tint/foil to verify the engine's lossless capsule.

For each candidate entry:

1. Obtain native and hardened-engine `decide_request` bytes before folding and compare them. Parse the native bytes with SDK and construct from_decide; compute both incremental begin_entry/apply_effect/finish_entry and project_verdict results and require equality. On a failed incremental effect, assert its whole projection equals the immediately preceding successful prefix, then retry a legal effect. A failed project_verdict must leave its starting projection unchanged.
2. Call native fixture and real hardened fixture on those same respective bytes and compare decoded verdicts. For accepted candidates, fold each engine in Admission mode and compare result/deltas. Also run one complete short sequence through fold_mediated itself to exercise the host trampoline; manually calling decide+fold alone does not establish mediator capability checks.
3. Compare exact engine snapshots and both viewer TableViews; reconstruct full per-view deltas where collected. Parse a fresh post-state authoritative request made with an unsubmitted no-op Game at the current next_seq, then compare its SDK projection to the computed projection. Never feed a PluginViewRequest or private-face-unveiled table into from_decide.
4. Compare projection table, current disclosures, allocator, next group ID and full active capsule/information. No production getter is necessary: compare cloned EffectProjection values after resetting only their per-entry bookkeeping by begin_entry on an unsubmitted empty Game on BOTH sides; assert table/disclosure values unchanged by that normalization. This uses existing PartialEq and preserves journal checks rather than comparing group_id alone. Compare plugin state separately in the engine snapshot.
5. At each named checkpoint save the complete engine snapshot, not just plugin_state. Instantiate NEW native/wasm engines and NEW native/wasm fixture instances, restore the same snapshot, and resume at the exact next input. Compare the cold pair's deltas to each other, not to a warm cache's incremental deltas. Final snapshots must equal the uninterrupted originating run. The new plugin must recover all command state from request bytes.

The projected equality intentionally omits engine-only face tint/foil because SDK Face does; exact engine-native/wasm equality and explicit restored face assertions cover those fields. Independently authored golden/negative inputs remain necessary because a shared SDK parser could otherwise conceal a common interpretation error.

For invalid structural Admission, expect no request and no sequence/mechanical/group change. For an already sequenced refusal preserve the engine's documented consumed-sequence behavior. For an invalid trusted verdict after fold_begin, compare mechanics/plugin/group/allocator unchanged and assert the agreed sequence result explicitly; do not incorrectly require whole snapshot equality across a consumed sequence. A plugin refusal before Admission consumes none.

## Small corpus with decisive checkpoints

A. Mechanical compensation (one baseline, despawn_any false and true subcases).

- Admit original cards with a known nontrivial vector order, a publicly revealed original token, a normal non-token, exhaustion/custom annotations, and an existing clamped card counter. Declare a second counter whose row is initially absent.
- For opcode1 use card_a as the normal card to exhaust/move to Deck, card_b as the original annotated token to Despawn, and card_c as a stable normal card holding both counter targets. Change card_c's existing counter past its clamp and create its formerly absent counter row before any optional Despawn; Spawn the transient token last. With despawn_any=true also Despawn card_c after its counter operations. The false-flag non-token refusal is a separate opcode8 vector. Ensure no owed Reveal exists before the hidden move; this case tests mechanics, not a bypass of disclosure guards.
- Save/reload while group is active and the original token is absent. Rollback, then apply a post-terminal cancellation annotation. Assert exact restored global card order, full faces, original counter value/row absence, original token/annotations and card placement/exhaustion; only the deliberate post-terminal annotation differs. No synthetic ordinary Move/Spawn events should be generated by restoration.
- Spawn again and assert IDs allocated by accepted rolled-back prefixes remain retired. Separate Begin→Spawn→Rollback in one accepted verdict retains high-water too. An adversarial verdict with Spawn then an invalid final effect must consume no tentative IDs; test active u32::MAX refusal. With despawn_any=false, non-token Despawn refuses and the prefix remains unchanged.

B. Disclosure wait, repeated requests and rollback audiences.

- Baseline c in Owner Aux, hidden/unrevealed; d in None Aux. Begin+Peek(d,1)+Move(c,All Aux)+Reveal(c). Save with actual owed c and exact d Peek audience. SDK current sets must match before any rollback.
- Duplicate Reveal(c) while already owed, then admit ONE public Reveal(c)+Continue. Save/reload; the group must remain decodable and ordinary continuation/Commit must work. Repeat with an unsolicited public Reveal before a later hidden→All request: old public entries cannot become credit for new debt.
- After the first fulfillment, move c None→All and request again. Save/reload with the second debt. For this Owner baseline, Rollback must retain the latest still-fulfillable owed obligation, with c not falsely considered fulfilled/revealed by the first public record. Assert owed c remains and a subsequent normal Reveal discharges it. Do not accept either success-or-error in the same test: Owner retains fulfillable debt; the separate None/transient cases below must refuse until fulfillment. Check current debt as well as final views.
- In a separate branch restored from that second-debt checkpoint, fulfill the latest request first, then Rollback. Returned Owner card must not become globally shown merely because its public entry happened in All; same-placement Owner reveal DOES produce shown. Run the same short disclosure case with baseline None: rollback before fulfillment refuses, after fulfillment succeeds but the restored deck remains hidden in both viewers. All baseline must not gain a spurious shown authorization. Preserve baseline grants and the exact d Peek audience.
- Separate active transient token: Spawn in None Aux, Peek, Despawn, save/reload, Rollback. This must be a valid history even though the historical Peek target is absent. A transient owed Reveal must instead block Despawn/Rollback until the latest normal public fulfillment; include request/fulfill/hidden-roundtrip/request-again.
- Parameterize request→Move(None), request→Despawn and request→token-shedding Move. Each refuses atomically, then succeeds after the exact normal public Reveal. Baseline owed-hidden snapshot can parse outside a group; Begin fails there, while independently legal ordinary Move(All)→Begin succeeds. No Reveal while None is introduced.

C. Capability and migration boundary (host tests, no full game).

- Existing WAT static-reply helper remains ABI0. Check ordinary accept with no group, attempted Begin rejection, and active-state rejection before decide. Use a trap-on-decide ABI0 fixture or a native call counter to prove it was not invoked. A bare accept active reply is not continuation capability. Include direct Decider with default protocol0 and a protocol1 toy Decider.
- Restore an independently authored old raw snapshot with no group keys into fresh native and wasm engines; emit the canonical v1 snapshot, run Begin and finish normally. Raw map with either new key (including null/0), unknown envelope version, duplicate keys/set elements, wrong group version/ID and invalid before/current allocation relation must reject through both restore exports. A failed restore leaves the prior instance state intact.
- Check the new ABI4 effect/request/snapshot golden bytes through SDK parse/encoding and real wasm request/restore paths. Keep old network wire goldens unchanged. Current-request ABI1 keys stay mandatory.

## One real HostSession/private-delivery test

Use net/tests/effect_groups.rs and the same hardened fixture, with two ClientSessions and the neutral TableConfig; no sockets or game setup. HostSession::intent automatically calls reveal_surfaced; relay the returned Game and Reveal entries in order. The fixture holds the group open after its Continue response to that Reveal. Do not manually call reveal_surfaced or inject log faces to make this pass.

Deliver host.owed_faces only to the addressed seat, then call both client plugin views. Assert d is visible only to its granted viewer, and its unique secret face bytes are absent from authoritative state, the mechanical capsule and DecideRequest even after the private view calls. c's face is now public journal/log data and may appear there. To demonstrate accepted public knowledge remains cached without globally revealing c, grant seat1 an ordinary Peek(c,1) afterward and do not deliver new OwnerFaces: the client can display the face harvested from the earlier public entry. Verify authoritative state still uses ordinary visibility and has no private injection. This is the cache claim that engine TableView comparisons alone cannot establish.

## Final source feasibility check and exact seams

- PluginModule requires Send+Sync and byte-oriented decide/view; a stateless NativeFixture satisfies it and explicitly overrides abi_version to 1. `load_plugin` returns AbiPlugin<WasmModule>; box it only for HostSession/ClientSession's `Option<Box<dyn PluginModule>>`. Do not attempt to give those constructors a bare SDK callback or SDK Verdict. Native adapter converts encoded SDK replies with agni_sim::abi::decode.
- The support module exports ordinary Rust `pub fn decide_bytes(&[u8])->Vec<u8>`, `pub fn view_bytes(&[u8])->Vec<u8>` and `pub const MANIFEST: &[u8]`. Only the example root invokes export_plugin!, with `crate::MANIFEST`, `crate::decide_bytes` and `crate::view_bytes`; host/net include the support module, not the export wrapper. The macro supplies the wasm `(ptr,len)->packed pointer/length` exports and ABI constant. The manifest must be actual CBOR for the five required PluginManifest fields (name/version/display/zones/hotkeys), not an empty map or runtime-owned temporary slice. Pin/decode it in a host test. No build.rs or game dependency is needed.
- Add the SDK example declaration with name `effect_group_fixture`, path `examples/effect_group_fixture.rs`, crate-type `["cdylib"]`, and `test = false`. Build this target explicitly. Read the produced filename from Cargo's artifact output or supply its verified path; do not confuse the example artifact under the target's examples directory with a package library wasm.
- Shared module loading must NOT copy host.rs's hard-coded `CARGO_MANIFEST_DIR/../..` into net tests: the host manifest requires `../..` to reach agni, while net requires `..`. Pass the resolved agni workspace root explicitly to shared helpers. Both new integration binaries require AGNI_EFFECT_GROUP_FIXTURE_WASM to name a prebuilt artifact and fail with a clear path message if absent; no nested fixture build under an active Cargo test lock. Preserve the existing engine fallback for old tests, but the acceptance invocation supplies AGNI_ENGINE_WASM too. Use absolute CARGO_TARGET_DIR. Load fresh runtime instances from cached hardened bytes.
- Fix the test budgets to the existing Riftbound parity values: engine 10,000,000,000 and plugin 100,000,000. This is not a claim that the fixture costs that much, nor permission to raise them if it traps. The smaller WAT ABI0 tests retain their existing small budgets.
- Current projection APIs provide table(), disclosures(), group_id(), next_group_id(), begin_entry, apply_effect, finish_entry and project_verdict. Full EffectProjection derives PartialEq/Eq. The proposed no-op normalization uses actual begin_entry behavior: Game changes no table/disclosure/information and resets only entry lifecycle fields. Normalize clones and compare them; never mutate the production projection with table_mut_for_projection to manufacture expected state. No new public active-group getter or production visibility API is required.
- The SDK repair's immutable despawn_any comes from authoritative Request/config and is retained inside EffectProjection. Test both configurations through engine-authored requests; do not place the flag in MechanicalState or mutate a parsed capsule to enable Despawn. Current disclosure sets come from decide state; view::parse may unveil separately supplied private faces and has no from_decide constructor. This distinction is exercised through public APIs, not test-only production escape hatches.
- HostSession::with_engine performs Genesis immediately. It cannot wrap an already restored active engine. Use it only for the fresh net scenario. For actual cold continuation use Engine::restore on fresh instances in the host corpus. Construct the two net clients via from_welcome_with with the exact host log, roster, viewer index, and separately loaded matching engine/plugin modules; relay subsequent entries with ClientSession::apply.
- ClientSession keeps faces private internally but exposes sufficient observations: add_faces for legitimately addressed OwnerFaces, plugin_view for its authorized SDK overlay, and table() for rendered visibility using the retained face cache. The net test therefore needs no getter/setter for private caches. Both clients harvest accepted Reveal entries through apply; subsequent Peek(c,1), with no new OwnerFaces, proves the face was retained. Do not claim an opaque cache assertion from snapshot bytes alone.
- The four protocol sequences above are acceptance requirements from the frozen contract, not new rules. In particular, the repeated-debt Owner branch retains fulfillable debt; None/transient rollback waits. Tests must use explicit expected outcomes, not accept either success or failure. If the repair source disagrees, return to protocol review rather than silently weakening these tests.

Ready as an implementation plan once the two repair reviews are green. Required source changes are test-support/example/dev-dependency wiring only; no new production networking constructor, engine rules knowledge, SDK private-face bypass or renderer API is proposed.
