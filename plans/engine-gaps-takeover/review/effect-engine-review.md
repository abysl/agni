# Neutral effect-group engine review

Candidate `40a69aa7` in `/tmp/agni-effect-groups`, base `870bddd4`, against the frozen implementation plan and final disclosure addendum. Engine-half source/test review only; no builds or edits. SDK absence is intentional and is not a blocker in this review.

**Disposition: changes required before engine-half approval.** This candidate implements the basic vocabulary and restoration shape, but important protocol acceptance remains unimplemented. Reported existing suite passes do not establish the new protocol's disclosure, malformed-snapshot or allocator guarantees.

## Must fix

1. **P1 — Snapshot migration and journal validation are absent.** `sim/src/log.rs::decode_state` (1407) simply deserializes `(u16, LogState)` or falls back to unrestricted raw `LogState`. Thus an unversioned map containing `effect_group`/`next_effect_group` is accepted; active group version/ID, duplicate and dangling card references, allocator bounds, disclosure invariants and vector limits are not checked. Serde BTreeSet/BTreeMap decoding can normalize duplicate entries before any later validator sees them. Implement the frozen bounded decoding/prescan and structural/semantic validation before admitting new groups; enforce limits before allocating capsule/information vectors, reject duplicate keys/set elements, validate current/capsule references against declarations and retained allocator, enforce group version and ID, and require full snapshot consumption. Legacy raw maps must lack BOTH new keys, even if their values are null/zero. Do not treat successful roundtrip of a valid self-written state as a migration safety test.

2. **P1 — Transient reveal obligations can be lost on rollback.** `rollback_effect_group` (1131–1145) uses a journal-wide `.any(PublicReveal for card)` to let a RequestReveal for an absent restored card disappear. This does not establish that the reveal followed the particular request. Concrete legal neutral sequence: create a card inside the group in an Aux zone; move it to a visibility-None Aux zone (Aux avoids token shedding), return to a revealable zone, request and fulfill Reveal; repeat the hidden/revealable move and RequestReveal, but do not fulfill the second request. Rollback incorrectly removes the transient card and its second owed face because the first Reveal exists. Check current outstanding obligations against the restored result, including transient cards, and reconcile requests/fulfillments in accepted order. Rollback must remain open until the latest request is fulfilled; an earlier reveal is not permission to erase later debt.

3. **P1 — Spawn allocator exhaustion is still unchecked.** An active-group Spawn reaches `apply_effect` → `Table::add_face`, whose `next_id += 1` can panic or wrap. The plan explicitly requires a checked active-group Spawn preflight, independently of the later A6 audit. Refuse before mutation at exhaustion; test both accepted rollback retaining allocation high-water and an entirely rejected verdict consuming none. Also move Begin's size checks before `state.mechanical()` clones the capsule: the current implementation allocates the whole capsule before deciding that it exceeds the feature limit.

4. **P2 — Unsupported actions reach admission and consume sequence before rejection.** `validate`/`validate_action` contain no active-action guard. `native_decide_request` consequently admits a structural Move/Reset/etc. to the plugin; `native_fold_entry` Admission calls `fold_begin`, incrementing next_seq, before `fold_finish` returns UnsupportedAction. Put the active Game/Reveal restriction in admission validation, retaining the fold_finish defense for trusted verdict entry points. Test that unsupported admission produces no request and leaves sequence/mechanics/group unchanged. Preserve the existing consumed-sequence rule for an already sequenced refusal. Validate the active first marker and matching ID before applying the entry to its tentative clone, as frozen, rather than after apply_action.

5. **P2 — Required protocol tests and goldens are missing.** Only five files changed; no new golden vector was added. New tests cover annotation+Spawn rollback, one empty-marker rejection and active snapshot roundtrip, raw migration, request stripping, and ABI0 active refusal. They do not exercise any disclosure reconciliation or rejection sequence. Add the bounded acceptance below before calling this engine implementation complete. Existing golden suite passing is not evidence for the new Effect/DecideRequest/snapshot shapes.

## Bounded implementation corrections

- `fold_mediated` calls `engine.decide_request` once for ABI0 checking and again through `mediate` for every ordinary ABI0 entry. Obtain one request, inspect its active group, then pass those same bytes to the plugin. This removes the introduced duplicate engine call/whole-state encoding without changing authorization. Keep the early ABI0 active rejection, the ABI0 attempt-to-Begin rejection, and direct-Decider capability guards. AbiPlugin's stored measured version and rejection of versions above 1 are sound.
- Indexed invalid lifecycle effects currently escape `fold_finish` as unindexed FoldError::EffectGroup. The frozen interface specifies BadEffect { index } for invalid indexed effects, with typed EffectGroup errors for pre-entry/membership checks. Align this before SDK implementation and add an exact error-shape assertion; do not silently change the agreed ABI error contract.

## Accepted structure and limits of this review

`Table::restore_cards_from` restores the original vector and retains max allocator; `restore_mechanical` replaces all eight intended mechanical fields without rewinding plugin state/configuration/next_seq/group counter. Snapshot framing and engine ABI4 are introduced. Begin/Continue/Commit/Rollback are the agreed text variants; effects after terminal run outside the group. A Reveal entry is recorded before a first-effect rollback, and the tentative verdict clone prevents ordinary failed effects from committing partial mechanics. Request stripping and PluginViewRequest stripping are present. PublicReveal reconciliation avoids calling ordinary Reveal on the restored Hand and conditionally sets shown only for the same Owner placement, which matches the intended audience rule. These parts are a useful implementation base, not substitutes for the missing acceptance above.

SDK projection tests belong to the next worker and are not requested in this engine-only gate. Fourth Costs still requires its separate cost cursor, plugin rules undo and reachable replacement/reveal continuations. A1 current-incarnation/allocation-high-water separation remains future work. No claim is made here of universal allocator-gas equality or a reproduced default-budget failure.
