# Effect-group SDK checkpoint review

Reviewed committed SDK/plugin changes at `3abea792` in `/tmp/agni-effect-groups`, using `git show` throughout. The other worker's dirty core/sim repair files were not reviewed. No builds or edits. Compared against the frozen interface and final disclosure feasibility contract.

**Disposition: changes required before SDK-half approval.** Required protocol keys and top-level disclosure-source corrections are closed; mechanical/disclosure projection is not yet equivalent to the contract.

## Concrete must-fixes

1. **P1 — Current disclosures are never projected.** `EffectProjection::apply_effect_inner` calls Snapshot::apply, but Snapshot intentionally treats Reveal/Peek as existence checks and carries no owed/peek/shown state. The wrapper never inserts owed_reveals for Reveal, adds Peek authorization, or clears disclosure state on Move/shed/Despawn. `begin_entry(Reveal)` records information but never clears the fulfilled owed/peek state or updates shown. Consequently Begin→Reveal→Move(None) can succeed without seeing the newly owed face, Commit loses new obligations, and baseline fulfilled obligations remain owed. Implement current disclosure transitions for ordinary entries/effects independently of the historical journal. Preserve exact engine clearing/show-in-place semantics and apply the active guards against the updated candidate. Post-terminal ordinary effects still need ordinary disclosure projection.

2. **P1 — Rollback rewinds accepted physical allocation.** `rollback` assigns `group.before.table` directly; it never retains max(current_next_id,before_next_id). A successful Begin→Spawn→Rollback therefore reuses the spawned ID. Restore the old vector/order/mechanics with the retained allocator high-water, including accepted same-verdict rollback, while a rejected project_verdict clone consumes none. Spawn's preflight exists, but alone does not establish allocator parity.

3. **P1 — Rollback information reconciliation differs from the frozen policy.** The PublicReveal arm inserts shown for any same-placement visible zone; it must do so only for Owner visibility. All-zone reveals must not add this extra authorization. Unknown plugin zones must not be treated as visible by `is_none_or`; resolve builtin Hand/Board explicitly and reject undeclared Plugin zones. The transient RequestReveal branch also copies the engine's erroneous journal-wide `.any(PublicReveal)` test: an earlier fulfilled request cannot discharge a later outstanding request. Preserve current outstanding obligations, including transient cards absent from the restored capsule, and process fulfillments in accepted order. Reuse the repeated-request transient Aux-zone regression from the engine review.

4. **P1 — Valid transient journals are rejected while malformed groups still parse.** `validate_information` rejects RequestReveal/RequestPeek whenever the card is absent from `before.table`, contrary to the explicit allowance for allocated transient IDs below current retained next_id. It also does not validate record seats or public reveal zone declarations. `decide::parse` never calls the semantic validation in from_decide, so unsupported group versions, group IDs >= next_effect_group, and invalid references can still return Some(Request). Freeze one shared validation path used by the public parser and projection constructor: allow legitimate transient records, reject future IDs/invalid audiences/undeclared zones, require before allocator <= current retained allocator, and validate current/capsule membership and immutable declarations.

5. **P1 — Decode bounds and duplicate/reference validation remain incomplete.** Current-state parsing is still the permissive old reader; it accepts repeated state keys and sorts new disclosure sets rather than rejecting bad canonical order/duplicates at parse time. `parse_record_card` accepts duplicate RequestReveal.card keys. `parse_counters` rejects only identical full CounterInfo rows, so duplicate target+counter keys with different values survive. `validate_disclosures` checks owed targets but not shown/peek live targets or peek seat validity, and it allows undeclared plugin placements. `validate_snapshot` does not validate card owner/seat/zone or duplicate counter keys. Capsule annotations check the aggregate limit only after allocating all per-card rows; enforce remaining aggregate capacity before each allocation. Peek decoding uses 4096×256 before discovering the actual seated-count limit, instead of the frozen checked 4096×seated count bound. Complete the bounded parser/validation checks without silently normalizing invalid journals.

6. **P2 — Group restrictions incorrectly apply to nongroup preparation.** from_decide and finish_entry always call the outstanding-fulfillment validator, even without an active group. The frozen policy allows a legacy nongroup owed-hidden state to decode and, where independently legal, move its card to a revealable placement before Begin. Separate structural disclosure validation from the active/Begin fulfillability constraint, and preserve ordinary nongroup semantics. Do not solve this by dropping old debt or allowing a Reveal in a None zone.

7. **P2 — First-marker APIs disagree.** `is_membership` includes Begin. For an already active entry whose first effect is Begin, incremental apply_effect returns AlreadyOpen, while project_verdict returns MissingMembership. The reference API and incremental API must agree: only Continue/Commit/Rollback are active first markers; all four lifecycle variants remain forbidden after a terminal. Wrong-ID failures must leave lifecycle flags unchanged. Current clone-and-commit apply_effect is a sound effect-level atomicity base.

## Existing SDK capability that the new neutral contract must account for

Snapshot does not project genesis `despawn_any`, and its ordinary Despawn always rejects a non-token. The engine permits that operation when despawn_any=true. This predates the checkpoint, but the new generic mechanical wrapper cannot claim equality for the existing configuration without carrying and using it. Add the immutable projection flag from the current request/configuration, or explicitly resolve the capability limit with root before integration; do not encode it in the mutable rollback capsule or game plugin state. A non-token Despawn plus rollback under despawn_any=true is the decisive vector.

## Confirmed portions

- `decide::parse` now requires effect_group_protocol, next_effect_group and effect_group, rejects protocol !=1, rejects duplicate top-level required keys, and requires input exhaustion. Missing-key/protocol0 acceptance is closed.
- Current disclosures come exclusively from parsed `state`; a top-level disclosures key is ignored. The earlier override bug is closed in source. Add order-independent negative tests to retain this boundary.
- Plugin ABI constants are raised to 1; SDK encodes all four agreed text-map Effect names. Group, capsule and public record field names match the frozen wire shape. The parser projects full public faces to the existing SDK subset without private view overlays.
- apply_effect clones the full projection before mutation, so its errors preserve prior successful effects and do not poison later membership retries. Ordinary effects after Commit are allowed and another lifecycle is refused. project_verdict clones the starting state. These provide the intended effect/verdict atomicity structure once state transitions and guards are complete.
- Capsule parsing preserves card vector order and includes the intended fields. Group/card identity is integer based; no pointer cache or nondeterministic collection iteration was introduced here.
