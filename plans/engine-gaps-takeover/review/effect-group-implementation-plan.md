# Implementable effect-group protocol, revision 1

Source: `/tmp/agni-takeover-costs` plus `/tmp/agni-effect-group-callers.md`; refined from `review/cost-undo-seam-review.md`. Read-only design and source double-check; no builds. This is the neutral prerequisite for fourth-cluster Costs. The first three Costs clusters remain independent.

## Fixed scope and choices

Use **one active group for the engine's one plugin-state lane**, not one group per seat. Different seats can legitimately answer the same replacement. The authoritative plugin verdict controls membership; an arbitrary Game payload cannot supply effects directly. There is presently no multiple-plugin owner field in LogState; do not invent a plugin hash registry here.

Choose a full **mechanical capsule** at Begin for the first implementation, rather than per-card inverse optimization. It is finite, exact, simpler to validate against the current fold, and contains no nested LogState/plugin blob/journal. A compact dirty-record journal is a later optimization with identical semantics. Capsule fields are:

`MechanicalState { table: Table, annotations, counters, tokens, revealed, owed_reveals, peeks, shown }`

These are the actual engine fields/types, including full CardFace and exact global card order/counter-row presence. Configuration, seats, counter declarations, options, plugin_state, next_seq and group metadata are excluded. Cards in private zones retain only the face already present in authoritative engine state; never capture the SDK view overlay. No rollback through ordinary Move/Spawn/Counter effects.

`LogState` gains `next_effect_group: u64` (default 0) and `effect_group: Option<EffectGroup>` (default None). `EffectGroup { version: 1, id: u64, before: MechanicalState, information: Vec<InformationRecord> }`. IDs are monotonically allocated: Begin must name exactly next_effect_group and checked-increment it. No wrapping, saturation, same-ID restart or nesting. Rollback does not rewind this counter.

## Wire vocabulary and lifecycle

Effects are serde externally tagged **text maps**, not numeric tags. Add matching neutral sim/SDK variants:

- `BeginEffectGroup { id: u64 }`
- `ContinueEffectGroup { id: u64 }`
- `CommitEffectGroup { id: u64 }`
- `RollbackEffectGroup { id: u64 }`

For example Begin encodes as `{"BeginEffectGroup":{"id":0}}`; Continue is a membership assertion, not a new checkpoint. Four names are intentional: three lifecycle operations alone cannot distinguish an admitted continuation from unrelated accepted work while a group is open.

When no group is active, ordinary effects behave as before. Begin may occur after earlier effects in a verdict: its capsule starts exactly there, immediately before the first payment mutation. Only one Begin is allowed in a verdict. A new group cannot be reopened in the verdict that closes another; this avoids ambiguous membership of subsequent effects.

When a group is already active, accept only LogAction::Game or LogAction::Reveal, and require the accepted verdict's first effect to be Continue, Commit or Rollback naming that group. Reject Move/Counter/Annotate/Spawn/Reset/Clear/Join and other structural actions before applying them. Replacement answers and payment-resource abilities use Game; required public face arrivals use Reveal. Fourth Costs must use explicit Game picks for declaration objects, not saved discard-Move gestures which mutate before payment. A later generic action-membership extension is separate.

After Continue, ordinary effects join the active group until exactly one terminal operation or the end of the verdict. Commit discards its capsule/information journal and keeps current state. Rollback restores/reconciles as below. Following effects run outside the closed group, allowing declaration cancellation and subsequent normal cleanup. A terminal operation with no active group, incorrect ID, second terminal operation, or new Begin is a deterministic BadEffect. No special authority is granted to the initiating seat: the plugin validates each current prompt's chooser and returns membership only for legitimate continuation inputs.

This is a mechanical guard, not an interpreter for opaque Game bytes. The plugin must block unrelated end-turn/play/activation actions while its payment frame is open. It must not emit Continue for them. Free-table/game-abort, if supported during a payment, explicitly rolls back and then performs its normal transition; do not clear the journal as a side effect of Reset.

## Atomic fold integration

`sim/src/log.rs::fold_finish` must validate membership before applying the entry, even for a zero-effect verdict. Use the cloned-next-state path whenever a group is active or any group operation is present. Rejected verdicts, invalid IDs, invalid information records and effect failures leave mechanical/group/plugin state unchanged. Keep the existing sequenced-log policy: fold_begin already consumes next_seq; this change does not rewind that sequence on a sequenced refusal. Admission validation must reject unsupported action kinds before fold_begin, as existing validate does for other restrictions.

Record only successful mutations/information events on the cloned state. At Begin copy the capsule from the post-entry, post-prefix state. At an accepted Reveal entry while active, record its information once alongside applying that entry; do not wait for Continue to take a new baseline. The engine's full-request clone handles a later failure in that same verdict. Update both native_fold_entry and direct fold_entry_with paths; no bypass through an empty effect list.

A runtime call failure while calculating a verdict emits nothing. An invalid continuation answer refuses only that answer; it does not undo a previously accepted payment prefix. Failed final game legality uses an explicit accepted Rollback verdict, followed by plugin cancellation. General kill/replacement callback completion remains the bounded D1 side of the prerequisite.

## Exact information reconciliation

Mechanical state and **delivered knowledge** are different. Keep accepted log entries and host/client face caches; rollback is not a Reset, Clear or hidden Move entry and must not invoke their cache-erasing handlers. The journal stores no seat-private face payload. Use these records, appended in accepted order:

`PublicReveal { card, face, zone_at_reveal, seat_at_reveal }`
`RequestReveal { card }`
`RequestPeek { card, seat }`

PublicReveal comes only from an accepted LogAction::Reveal, whose face is already public log input. The request variants come from validated Effect::Reveal/Peek; they contain IDs/audience only. Begin captures the baseline disclosure sets. Ordinary Move/Despawn clearing those sets is mechanical and needs no separate information record. A mere private face arriving in a view or network OwnerFaces message is never journal input.

Rollback first restores the capsule, then processes information records in order for cards that existed in the capsule and still exist after restoration. Records for group-created/transient objects are discarded; their already accepted public history remains in the log. Resolve each remaining record as follows:

1. RequestReveal: if the restored card is not in revealed, retain owed_reveals for it. This preserves an accepted disclosure obligation, even if its fulfillment needs normal host sequencing after rollback.
2. RequestPeek: if the card is not already public/revealed, retain that exact seat's peek authorization; validate the seat against the unchanged roster. Never broaden the audience.
3. PublicReveal: remove owed_reveals for that card (it was fulfilled). If its restored zone has visibility None, leave its restored face/revealed/shown state unchanged; the prior public face remains in log/knowledge caches, not as a globally visible deck card. Otherwise install that public face and mark revealed. Clear redundant peek authorizations only when the face becomes public in the restored state. Preserve baseline shown; add shown for an Owner zone only when `(zone, seat)` equals the recorded reveal placement. A public reveal while temporarily in Chain/Trash must not expose the returned Hand card globally merely by setting shown. Existing public-zone visibility already exposes the restored public face.

The distinction in step 3 is necessary because `table_view` uses shown/peek grants to expose private zones, and `own_faces` is a separate overlay. Do not call apply_action(Reveal) blindly at the restored location: its show_in_place would expose a returned private card. Do not union the four disclosure sets indiscriminately. Legitimate pending obligations/seat grants survive; already delivered knowledge stays in caches/log even where restored zone visibility hides the card again. This is the version-1 neutral information policy, not permission to undo a disclosure.

After reconciliation, no set may reference a removed object or nonexistent seat. Preserve preexisting obligations from the capsule unless a retained PublicReveal fulfilled them. Commit performs no reconciliation: ordinary current state is already authoritative.

## Allocators and A1

For any Rollback, restore the capsule's cards and exact order but set physical next_id to `max(current_next_id, before_next_id)`. Removed newly allocated IDs stay retired. Begin/rollback in one **accepted** verdict follows this same deterministic policy; an entirely rejected clone consumes none of its tentative allocations. Never rewind next_seq or next_effect_group.

Add a small game-neutral Table operation to restore another Table's card contents while retaining the maximum allocator cursor; do not rebuild through insert_card because it appends and does not preserve exact global order. Preflight Spawn cursor exhaustion with checked arithmetic before an active-group spawn and mirror that refusal in the SDK. The general A6 allocator audit remains separately tracked.

When A1 is added, the capsule restores each preexisting object's original current ObjectRef while preserving generation allocation high-water. Current incarnation and next generation must be separable; intermediate committed incarnations remain retired. No rule Event::Moved/Played/Died arises from the internal restore itself.

## SDK projection and request boundary

Keep the authoritative journal in LogState/snapshots. Add top-level DecideRequest keys `effect_group_protocol: 1`, `next_effect_group`, and `effect_group` containing the public projected group. Strip the full engine journal fields from the `state` copy sent to plugins and from PluginViewRequest::of/seen_by. This avoids duplicating the capsule and gives the SDK one explicit journal input. Engine snapshots continue to store the full lossless capsule.

SDK `decide::Request` parses the protocol/counter/group. Add projected `MechanicalSnapshot` and `EffectGroupProjection` types in `plugins/sdk/src/table.rs` or a small `effect_group.rs`; the before body excludes nested group state. SDK projection may omit core tint/foil as it already does, but the authoritative engine capsule may not. SDK Begin captures only its authoritative public Snapshot projection; the emitted effect contains **only the ID**, never that capture. Engine independently captures its own state.

Provide a projection state containing `{ table: Snapshot, next_effect_group, active_group }` and pure apply_entry/apply_effect lifecycle methods. The existing table methods remain the ordinary operation implementation. This wrapper is passed to authoritative execution; view code can quote costs but has no authoritative group constructor/export. Adapt Ctx::emit/replay_table in a later isolated plugin-integration step, rather than teaching neutral SDK code about Riftbound's Ctx or GameBlob. Ctx reconstruction receives the request's group projection; Ctx::enter's two copies and replay_table reconstruction must not double-record information globally. Each projected snapshot contains its own deterministic journal, and the final engine fold remains the sole authoritative writer.

On SDK Rollback, use the identical field replacement, allocator-max and information-reconciliation rules on its projection. The decisive equality is `project(engine_after) == sdk_after`; SDK's reduced face representation is not a lossless engine snapshot serializer. Return no plugin rules state from the neutral journal. The Costs plugin separately restores its leaf rules body (pools/promises/pending death/trigger work), then emits cancellation effects against the restored SDK table. The payment cursor covers Spend::Kill resource sources such as Gold as well as new additional kill/discard/exhaust operations.

## Versions, migration and explicit limits

- Engine ABI: `sim/src/abi.rs::ENGINE_ABI_VERSION` 3→4; guest exports/host mismatch tests and hardened metadata follow it. Exports remain unchanged.
- Plugin ABI: SDK constant 0→1 and Riftbound/MTG declared constants/tests follow. AbiPlugin::load currently ignores the returned version; change it to accept explicitly supported versions 0 and 1, reject others. ABI-0 plugins remain valid on ABI-4 engines with no groups. ABI-1 decide parsing requires effect_group_protocol=1, so it refuses an old engine request rather than emitting unsupported effects. Do not assume old-host AbiPlugin had a protective version check.
- Engine snapshots: introduce `STATE_SNAPSHOT_VERSION = 1` and encode `[1, LogState]` in encode_state. decode_state accepts that exact envelope or an old raw-map LogState **only when the new group/counter keys are absent**; migrate old state with None/0. Unknown versions/wrong arity/ambiguous raw maps are rejected. Direct ABI state objects remain LogState maps, not nested snapshot envelopes. All snapshot consumers already use encode_state/decode_state or opaque bytes; audit their tests as listed in the caller manifest.
- Plugin blob: no neutral journal in GameBlob. Fourth Costs adds its own versioned owner/cursor/leaf-rules-undo frame; the first three clusters' v12 blob stays unchanged until that integration.
- Wire/log actions: WIRE_VERSION 6 and LogAction tags stay unchanged; lifecycle operations are plugin verdict effects reproduced by the pinned engine/plugin. Do not regenerate unrelated network message goldens. A new network journal message would require a separate wire design and is not part of this plan.
- Deterministic feature limits for revision 1: one group; at Begin at most 4096 cards, 16384 counter rows and 16384 annotation entries; at most 4096 information records while open. Validate before capture/append and reject before partial mutation. These are explicit group-feature limits, not truncations or a claim that broader A6 limits are fixed. Use checked arithmetic for counters and IDs; bounded decode validates the same limits. Preserve all old golden inputs. Add new effect, request and snapshot golden fixtures under the ABI/snapshot version bump; AGNI_GOLDEN_WRITE only with those version changes.

## Self-review against current source

The initial high-level proposal needed four corrections now resolved: effects have text names, not numeric tags; one plugin_state means group ownership is plugin-lane-wide, not seat-wide; AbiPlugin did not enforce version equality; and fold_finish's empty-effect fast path plus pre-effect incoming Reveal need explicit membership/information handling. Snapshot::unveil is view-only and never enters the new capture path. Table's private allocator/order require an actual restoration helper. Replaying ordinary Reveal after restoring Hand would call show_in_place and overexpose it, so reconciliation is explicit. Group restore cannot restore recursive LogState/plugin snapshots or reset accepted allocation/sequence history.

Remaining prerequisite, not hidden by this protocol: the plugin must serialize its rules undo and terminal replacement result. Neutral effect groups make mechanical compensation possible; they do not pause arbitrary Rust callbacks. First three Costs remain unblocked; fourth is not complete until its combined continuation/undo acceptance passes.

## Frozen implementation interface (supersedes earlier open choices)

**CBOR:** use existing serde text-map conventions. The exact full group map is `{ "version": 1, "id": <u64>, "before": <MechanicalState>, "information": [<InformationRecord>...] }`. Its before map has exactly these required keys: `table`, `annotations`, `counters`, `tokens`, `revealed`, `owed_reveals`, `peeks`, `shown`. Nested encodings are the existing LogState field encodings: Table's `{cards,next_id}`, core Card/Face maps, annotation map, CounterValue maps, unsigned-ID sets encoded as arrays, and `(card,seat)` peek pairs encoded as two-element arrays. Preserve card vector order. Information records use externally tagged maps named `PublicReveal`, `RequestReveal`, `RequestPeek`; fields are exactly those specified above, with `zone_at_reveal` using the existing core Zone representation and `seat_at_reveal` u8. Lifecycle effect payloads contain only `id`.

New LogState serialized key names are exactly `next_effect_group` and `effect_group`, with defaults 0/None and omission for those defaults. The request's `effect_group_protocol` is required u16 value 1; `next_effect_group` is required u64 even when zero; `effect_group` is required null or the full group map above. For revision 1, **use the same public mechanical capsule encoding in the request group as in the engine group**, including publicly sourced full CardFace fields. The SDK projects that payload while parsing; do not create a second independently named capsule wire shape. This replaces the earlier potentially ambiguous phrase “projected group.” There are no private overlays in either capsule.

Build a decide request by first copying the real counter/group into its top-level keys, then removing them from the cloned `state` body (set defaults and omit); retain the existing extraction of plugin_state. `PluginViewRequest::of`/`seen_by` also omit group/counter from their state clone and do not add the top-level journal fields. Neither operation mutates the original LogState. Snapshot encoding stores the original full group/counter, never the stripped request state. Add tests for all three byte shapes: snapshot has one journal, decide request has one journal at top level, plugin view has none.

SDK public signatures, with Rust names frozen:

- `decide::Request` retains current fields and adds `effect_group_protocol: u16`, `next_effect_group: u64`, `effect_group: Option<EffectGroupProjection>`, and `disclosures: DisclosureProjection` for current state's owed/peek/shown fields.
- `effect_group::MechanicalProjection { table: Snapshot, disclosures: DisclosureProjection }`; its table contains only the existing mechanical projection fields with immutable zone/counter/player configuration copied from the current request during parsing. It has no group/counter/journal of its own.
- `DisclosureProjection { owed_reveals: Vec<u32>, peeks: Vec<(u32,u8)>, shown: Vec<u32> }`; vectors are sorted/unique. `Snapshot.revealed` remains the revealed set; do not duplicate it here.
- `EffectGroupProjection { version: u16, id: u64, before: MechanicalProjection, information: Vec<InformationProjection> }`, with InformationProjection matching the three record cases and SDK Face for its public face subset.
- `EffectProjection::from_decide(request: &decide::Request) -> Result<Self, GroupError>` copies authoritative parsed state/group only; there is no corresponding constructor from view::Request. A cfg(test) constructor may create toy projections. Runtime fields are private, with `table(&self) -> &Snapshot`, `table_mut_for_projection(&mut self) -> &mut Snapshot` restricted to the authoritative integration, `group_id(&self) -> Option<u64>`, and `next_group_id(&self) -> u64`.
- `begin_entry(&mut self, action: &Action, actor: u8) -> Result<(), ProjectionError>` validates the allowed action class and applies it, including one information record. It records whether a group was active at entry start and resets per-entry lifecycle/membership tracking. It does not checkpoint or accept the input.
- `apply_effect(&mut self, effect: &Effect, actor: u8) -> Result<(), ProjectionError>` enforces the first-effect marker when a group was active at entry start, then implements the matching lifecycle/ordinary effect and successful information recording. Every call is atomic with respect to its own failure. Earlier successful calls remain in the tentative entry projection.
- `finish_entry(&self) -> Result<(), GroupError>` rejects an active-at-start entry without a valid first marker and enforces the one-Begin/one-terminal rules. Ctx finish must call this before producing a verdict.
- `project_verdict(&self, action: &Action, effects: &[Effect], actor: u8) -> Result<Self, ProjectionError>` is the reference/testing API: clone self, begin_entry, apply each effect, finish_entry, return the clone. It leaves self unchanged on error. Ctx's incremental path must match it exactly.

`ProjectionError = Apply(ApplyError) | Group(GroupError)`. Freeze GroupError variants: `UnsupportedProtocol`, `MissingMembership`, `WrongGroup`, `AlreadyOpen`, `NotOpen`, `InvalidLifecycle`, `UnsupportedAction`, `IdExhausted`, `LimitExceeded`, `InvalidJournal`, `OutstandingDisclosure`. No implicit default-group selection. SDK decode returns None for malformed request/journal; runtime lifecycle methods return typed errors. In sim add `FoldError::EffectGroup { error: EffectGroupError }` with the same names for pre-entry/membership errors; retain `BadEffect { index }` for an invalid indexed lifecycle/effect so existing indexed-error behavior is preserved. Diagnostic engine replies may name the internal typed cause; don't put card-rule names into SDK errors.

**ABI-0 enforcement:** store the measured version in AbiPlugin. Add `PluginModule::abi_version(&self) -> u32` (default 0 for legacy adapters; AbiPlugin returns the measured value). In fold_mediated, refuse an active-group request before invoking/folding an ABI-0 plugin, and reject any lifecycle effect returned by ABI 0 even if it spells a valid marker. Add the equivalent `Decider::effect_group_protocol(&self) -> u16` default 0 and guard in fold_entry_with for direct native deciders; group-capable toy/Riftbound deciders return 1. The low-level fold_finish/native_fold_entry APIs consume an already mediated trusted verdict and continue to enforce lifecycle membership themselves; they do not discover a module version from opaque Game bytes. Explicitly test both mediated and direct-Decider paths; testing only raw fold_finish is insufficient for ABI authorization.

**Decode bounds:** before allocating each new capsule vector, bound advertised lengths to the fixed revision-1 limits; peek/shown/revealed/owed/token sets may have at most 4096 cards (peeks at most 4096×current seated count with checked multiplication). Validate version==1; id < next_effect_group; unique card IDs; each card ID below the retained allocator cursor; exact existing card order; sorted/unique set vectors; token/disclosure card references in the capsule; counter targets/scopes and seat IDs valid under current immutable declarations; no duplicate annotation/card/map keys. Information record IDs may name an allocated transient card absent from before/current, but must be below the current retained allocator cursor; no unknown future IDs. Validate every record tag/payload and seat/zone, not just array length. Engine and SDK reject the same projected-invalid journal. Do not accept new group keys in an unversioned raw snapshot and silently discard them.

**Outstanding-disclosure correction from self-review:** a newly accepted RequestReveal can refer to a card which rollback would return to a visibility-None zone; current validate_action forbids revealing such a card there. It is not sound to promise ordinary host fulfillment after restoring it. Before committing Rollback, compute reconciliation on a scratch capsule: if any still-unfulfilled disclosure introduced by the group would require a Reveal in a restored visibility-None zone, return OutstandingDisclosure without mutation and keep the group open. The plugin waits for the normal logged Reveal while the card remains at its current revealable placement, then retries rollback. Also refuse an in-group mechanical operation that would strand an outstanding public Reveal in a non-revealable location. This prevents an accepted group from becoming unfinishable under the existing Reveal vocabulary; it is an explicit lifecycle constraint, not an invented Reveal bypass. A fulfilled PublicReveal may still roll back into a hidden zone using the knowledge-preserving rules above. Include a test which first rejects rollback, fulfills the exact owed face, then rolls back successfully.

**Latest version reservation:** Damage owns Riftbound blob v13. The subsequent additional-Costs frame uses the next version after the final integrated plugin baseline (v14 if no other intervening bump). Neutral engine snapshot v1, engine ABI4 and plugin ABI1 are independent of that reservation.

## Final disclosure feasibility contract (frozen; supersedes weaker guard wording)

The neutral protocol is ready for implementation with the rules below. Fourth Costs is **not** ready merely because these guards exist: its explicit payment cursor and reachable helper continuations remain a separate required implementation and acceptance gate.

Source confirmation: `engine/hide.rs::reveal_before` only narrates and calls `drop_facedown`; the latter clears hidden plugin fields and the hidden annotation. Neither emits `Effect::Reveal`. `Ctx::recycle_to_bottom` calls it and immediately moves the card to Deck; bounce similarly continues to Hand or token Despawn. This is a concrete missing reveal/wait seam, not an existing asynchronous helper that can be reused unchanged. `Ctx::reveal_top` instead moves Deck→Chain and requests Reveal. `net::host::reveal_surfaced` can fulfill owed faces in All/Owner zones, never None; removing a plugin annotation is not a substitute for the logged Reveal. No new authority to reveal a card in None is introduced.

**Exact neutral semantics:** define an outstanding public disclosure as a live card in `owed_reveals` and absent from `revealed`. Its currently declared zone must have visibility All or Owner to be fulfillable. Missing/undeclared placement is also unfulfillable.

- **Begin:** reject with OutstandingDisclosure if any baseline outstanding disclosure is unfulfillable, before capture or advancing the group ID. A revealable baseline obligation is allowed and is captured normally. Legacy snapshots with owed-hidden cards may still decode; do not silently clear, rebind or satisfy them. The plugin must first perform an independently legal operation outside a group that makes the card revealable and arrange the ordinary logged Reveal. No generic deck-to-Chain move is implied by this protocol. If no such operation is legal, group admission remains refused for that state.
- **RequestReveal:** inside a group, an unfulfilled `Effect::Reveal` on a currently None/missing-placement card fails with OutstandingDisclosure immediately, even if a later effect in the same verdict would move it to All. A game-authorized reveal-from-deck operation must emit its actual move to a revealable zone first, then request Reveal and save its continuation. Already revealed cards retain the existing no-op behavior. The strict prefix rule makes incremental SDK projection match the engine; there is no end-of-verdict repair exception.
- **Move/Despawn:** before an ordinary effect, simulate its mechanical result. Reject if an outstanding disclosure would be erased, lose its live card, or have a resulting None/undeclared placement. This covers explicit Despawn, token shedding caused by Move, and any effect that clears the obligation without an accepted Reveal. A no-op Move is unchanged. Relocation to another valid All/Owner placement is mechanically allowed if the obligation remains fulfillable; card rules requiring reveal *before leaving* impose the stronger cursor boundary below. Do not infer that generic engine permission satisfies that rule.
- **Rollback:** compute restoration and reconciliation on scratch state. Every currently outstanding obligation must either have a fulfilled public Reveal in accepted history since its request, or remain attached to a restored live card in a revealable placement. Reject otherwise. In particular, rollback cannot discard an unfulfilled obligation for a newly spawned card simply because that card was absent from the capsule; await its Reveal before erasing it. Also reject newly reconstructed outstanding obligations on restored None/absent cards. Baseline obligations and group-created obligations receive the same check. Fulfilled transient information may be omitted from restored state while its accepted log history remains.
- **Continue/Commit:** Continue does not change obligations. Commit may retain outstanding obligations only in valid revealable placements, where the ordinary host sequencer can fulfill them after the group closes. Neither terminal operation fabricates a face, treats a Peek as a public Reveal, or clears debt merely to finish. Snapshot decode rejects active journals violating this live/fulfillable invariant; legacy nongroup states are not silently normalized.

Apply the invariant after every tentative group operation as well as Begin/Rollback; preflight and failure leave the tentative effect unchanged. Whole-verdict rejection discards the clone as already specified. These checks refer to explicit owed public disclosures. Host automatic surfacing of public arrivals is **not** sufficient to protect an intermediate move when two effects occur in one verdict; the plugin must explicitly request/wait when a legal payment sequence requires that disclosure before its next operation. Do not classify every unrevealed All-zone card as owing a face: intentionally facedown plays also occupy All zones, and host hidden-play bookkeeping is not neutral engine game knowledge.

**Required Costs continuation coverage:** serialize the complete payment plan, current operation and substage, affected card/actor/destination, exact awaited public card IDs, and terminal replacement result in the cost-owned frame. For a legal reveal-before-leave operation, emit explicit Reveal while still at the required revealable pre-move placement, save `AwaitPublicReveal`, and return immediately. On the matching admitted Reveal, advance exactly once to the stored move/despawn and its suffix. Other Reveal entries may service other obligations but cannot complete this cursor. The face must come from that logged input/authoritative public projection, never a private view overlay. Existing prefix changes remain visible while waiting; do not replay them or mark payment complete early.

The bounded caller inventory must include all operations reachable from the **whole** plan: source exhaust and Spend::Kill (Gold), rune exhaust/recycle, burn/discard, additional kill/discard/exhaust, their trash replacements, and any replacement continuation that bounces, recycles, banishes or removes a facedown card/token. Simple already-public rune recycling needs no invented reveal wait. Hidden-leave helpers need the actual explicit Reveal seam above; discard/burn arrivals that need a face before branching or another move must request it at their legal revealable destination and await it. `discard::resume_with` already has a saved unknown-face path, but it is not proof that direct Ctx discard/burn helpers or every cost caller share that continuation. Record each reachable helper's completion contract before claiming the fourth cluster complete. Broader nonpayment synchronous helper debt remains separately inventoried.

**Decisive sequence tests:** (1) start with a facedown card at an All placement; an accepted cost prefix opens a group, requests Reveal and saves before recycling; save engine snapshot plus plugin frame and rebuild. Assert the card has not moved and payment is incomplete. Feed the exact ordinary Reveal, verify the saved cursor performs the move once, then force final legality refusal and rollback. The original card placement/state returns, accepted public knowledge remains, group allocation/log sequence do not rewind, and private-view face changes never affect bytes. (2) show that Reveal→Move(None), Reveal→Despawn and Reveal→token-shedding Move in one verdict refuse atomically, while Reveal/save→logged Reveal→same operation succeeds. Include an owed group-created card: rollback must wait before deleting it. (3) RequestReveal on a None card rejects; legal Move(All)→RequestReveal succeeds but its immediate Rollback-to-None waits. Baseline owed-hidden Begin rejects; baseline owed-revealable Begin/save/Reveal/rollback succeeds. (4) run a complete resource-plus-additional plan through a Gold replacement wait and a disclosure wait across independent requests, then refusal: no duplicate resource payment, death/trigger events or suffix, and no omitted original disclosure. Native, SDK projection and pinned engine/plugin replay must agree at every admitted boundary.

Disposition: **neutral protocol ready, with the strict guards and vectors above included in its implementation scope.** The separate cost cursor/leaf-rules undo and reachable replacement/reveal continuations are still blockers to declaring fourth Costs recovered. Guard-induced refusal of a legal sequence is a failed integration test, not an acceptable substitute for implementing its suspension.
